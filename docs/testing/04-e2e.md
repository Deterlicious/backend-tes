# 🔴 End-to-End (E2E) Testing

> **Tujuan**: Menguji alur bisnis lengkap dari awal hingga akhir pada server yang berjalan nyata.  
> **Tool**: Bruno / Postman Collection / cURL.  
> **Catatan**: E2E berjalan terhadap server `localhost`, bukan MongoDB Memory Server.

### Variabel Environment E2E

```
BASE_URL    = http://localhost:4000/api
AKUN_TOKEN  = (diisi setelah login owner)
PIN_TOKEN   = (diisi setelah login PIN kasir)
TENANT_ID   = (diisi setelah setup tenant)
```

---

## E2E-01: Setup Toko Baru (Onboarding)

**Alur**: Registrasi → Login → Buat Tenant → Setup Role → Buat Kasir → Login PIN

**Step 1 — Registrasi Akun Owner**
```
POST /api/akun/auth/register
```
```json
{ "email": "owner@kafe-contoh.com", "password": "KafeOwner2026!", "username": "owner_kafe" }
```
✅ Expected: `201 Created`

**Step 2 — Login Owner**
```
POST /api/akun/auth/login
```
```json
{ "email": "owner@kafe-contoh.com", "password": "KafeOwner2026!", "deviceID": "desktop-kasir-01" }
```
✅ Expected: `200 OK` + simpan `accessToken` → `AKUN_TOKEN`

**Step 3 — Buat Tenant (Toko)**
```
POST /api/tenant
Authorization: Bearer {{AKUN_TOKEN}}
```
```json
{
  "namaToko": "Kafe Contoh Makmur",
  "alamat": "Jl. Sudirman No. 45",
  "kota": "Jakarta",
  "persenPajak": 11,
  "tipePajak": "Belum Termasuk (Exclusive)"
}
```
✅ Expected: `201 Created` + simpan `tenantID`

**Step 4 — Buat Role Kasir**
```
POST /api/role
Authorization: Bearer {{AKUN_TOKEN}}
```
```json
{ "namaRole": "Kasir", "deskripsi": "Karyawan kasir" }
```
✅ Expected: `201 Created` + simpan `roleID`

**Step 5 — Buat Pengguna (Kasir)**
```
POST /api/pengguna/register-owner
Authorization: Bearer {{AKUN_TOKEN}}
```
```json
{ "nama": "Ahmad Kasir", "pin": "123456", "roleID": "{{ROLE_ID}}" }
```
✅ Expected: `201 Created`

**Step 6 — Login PIN Kasir**
```
POST /api/pengguna/pin-login
Authorization: Bearer {{AKUN_TOKEN}}
```
```json
{ "penggunaID": "{{PENGGUNA_ID}}", "pin": "123456" }
```
✅ Expected: `200 OK` + simpan `PIN_TOKEN`

## E2E-02: Transaksi POS Lengkap (Dine-In Cash)

**Alur**: Tambah Pelanggan → Buat Kategori → Buat Produk → Buat Penjualan → Bayar → Verifikasi PAID

**Step 1** — `POST /api/pelanggan` → simpan `pelangganID`  
**Step 2** — `POST /api/kategori` → simpan `kategoriID`  
**Step 3** — `POST /api/produk` → simpan `produkID`

**Step 4 — Buat Transaksi Penjualan**
```
POST /api/penjualan
Authorization: Bearer {{PIN_TOKEN}}
```
```json
{
  "noReferensi": "POS-E2E-001",
  "pelangganID": "{{PELANGGAN_ID}}",
  "jenisTransaksi": "POS",
  "jenisPenjualan": "dine-in",
  "tanggalTransaksi": "2026-03-26T08:00:00.000Z",
  "itemPenjualan": [{
    "produkID": "{{PRODUK_ID}}",
    "namaProduk": "Es Teh Manis",
    "jumlah": 3,
    "hargaJual": 8000,
    "subTotal": 24000,
    "jumlahDiskon": 0,
    "total": 24000,
    "jumlahPajak": 0,
    "totalharga": 24000
  }],
  "jumlahDiskonTransaksi": 0,
  "jumlahPajakTransaksi": 0,
  "totalDibayar": 0
}
```
✅ Expected: `201` + `statusBayar: "UNPAID"` + `totalTagihan: 24000` + simpan `penjualanID`

**Step 5 — Proses Pembayaran**
```
POST /api/pembayaran
Authorization: Bearer {{PIN_TOKEN}}
```
```json
{
  "penjualanID": "{{PENJUALAN_ID}}",
  "akunKasID": "{{AKUN_KAS_ID}}",
  "metodePembayaranID": "{{METODE_BAYAR_ID}}",
  "noReferensi": "POS-E2E-001",
  "jumlahBayar": 24000,
  "tanggalBayar": "2026-03-26T08:05:00.000Z",
  "status": "PAID"
}
```
✅ Expected: `201` + `status: "PAID"`

**Step 6 — Verifikasi Status Penjualan**
```
GET /api/penjualan/{{PENJUALAN_ID}}
Authorization: Bearer {{PIN_TOKEN}}
```
✅ Expected:
```json
{ "data": { "statusBayar": "PAID", "sisaTagihan": 0, "totalDibayar": 24000 } }
```

## E2E-03: Booking Sesi Aset (Meja Biliar)

**Alur**: Buat TipeAset → Buat Aset → Buat Tarif → Buka Sesi → Tutup Sesi → Bayar

**Step 1** — `POST /api/tipeaset` `{ "namaTipeAset": "Meja Biliar" }`  
**Step 2** — `POST /api/aset` `{ "namaAset": "Meja Biliar A", "tipeAsetID": "{{ID}}", "status": "tersedia" }`  
**Step 3** — `POST /api/tarif` `{ "namaTarif": "Tarif Normal", "hargaPerJam": 30000, "tipeAsetID": "{{ID}}" }`

**Step 4 — Buka Sesi Booking**
```
POST /api/sesibooking
Authorization: Bearer {{PIN_TOKEN}}
```
```json
{
  "dataPelanggan": "{{PELANGGAN_ID}}",
  "dataAset": "{{ASET_ID}}",
  "dataTarif": "{{TARIF_ID}}",
  "dataPenjualan": "{{PENJUALAN_ID}}",
  "waktuMulai": "2026-03-26T14:00:00.000Z",
  "status": "Aktif"
}
```
✅ Expected: `201` + `status: "Aktif"` + simpan `sesiID`

**Step 5 — Tutup Sesi**
```
PUT /api/sesibooking/{{SESI_ID}}
```
```json
{ "waktuSelesai": "2026-03-26T16:00:00.000Z", "status": "Selesai" }
```
✅ Expected: `200` + `durasiMenit: 120` + `status: "Selesai"`

## E2E-04: Keamanan Isolasi Data Antar Tenant

**Tujuan**: Memastikan data Tenant A tidak bisa diakses Tenant B.

**Step 1** — Login kasir Tenant A → buat produk `"Produk Rahasia"` → simpan `produkID`  
**Step 2** — Login kasir Tenant B (token berbeda)

**Step 3 — Akses produk Tenant A dengan token Tenant B**
```
GET /api/produk/{{PRODUK_ID_TENANT_A}}
Authorization: Bearer {{TOKEN_TENANT_B}}
```
✅ Expected: `404 Not Found`
```json
{ "message": "Resource tidak ditemukan (ID Invalid)." }
```

**Step 4** — Buat penjualan dengan `produkID` dari Tenant A  
✅ Expected: `400 Bad Request` atau `404 Not Found`

## E2E-05: Multi-Device Auth & Forced Logout

**Tujuan**: Token lama tidak valid setelah logout.

**Step 1** — Login Device 1 (`deviceID: "laptop-01"`) → simpan `TOKEN_1`

**Step 2 — Logout Device 1**
```
POST /api/akun/auth/logout
Authorization: Bearer {{TOKEN_1}}
```
✅ Expected: `200 OK`

**Step 3 — Pakai TOKEN_1 yang sudah logout**
```
GET /api/akun/auth/akun
Authorization: Bearer {{TOKEN_1}}
```
✅ Expected: `401 Unauthorized`
```json
{ "message": "Sesi telah berakhir di perangkat ini. Silakan login ulang." }
```
